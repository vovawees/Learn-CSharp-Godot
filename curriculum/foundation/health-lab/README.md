# Практика 1: здоровье после урона

В этой задаче ты отделишь игровое правило от ввода и вывода, сформулируешь проверки и реализуешь свой алгоритм. Полезно сначала прочитать [первые уроки](../README.md#урок-1-здоровье-после-урона).

## Идея

Метод — именованная операция. Аргументы дают ему исходные данные, а возвращаемое значение передаёт результат вызывающему коду. В отличие от консольного приложения урока 1, здесь метод не должен читать или печатать: это позволит проверять игровое правило независимо от интерфейса.

## ТЗ

Измени **только `Health.cs`**, сохрани класс `HealthLab.Health` и сигнатуру `public static int AfterDamage(int health, int damage)`:

- `health` и `damage` — целые числа от 0 до 100 включительно.
- Метод возвращает здоровье после удара. Урон уменьшает здоровье, но результат не может опуститься ниже нуля.
- Если хотя бы один аргумент выходит за допустимый диапазон, метод должен выбросить `ArgumentOutOfRangeException`.
- Выбор синтаксиса и алгоритма за тобой. Не меняй тестирующий `Program.cs`, чтобы получить зелёный результат.

Перед реализацией предскажи результаты для `(80, 30)`, `(20, 20)`, `(5, 99)`, `(0, 0)`, а также поведение для `(-1, 5)`. Запиши рассуждение в отдельный файл или блокнот.

## Запуск на ПК

Установи [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0). В терминале из корня репозитория:

```bash
dotnet --version
dotnet run --project curriculum/foundation/health-lab/HealthLab.csproj
```

Стартовый код специально не реализован: сначала будет ошибка тестов. Измени `Health.cs` и повтори запуск. Тестирующая программа выполняет твой метод на всех 10 201 допустимых парах и проверяет десять недопустимых случаев. Она показывает первые 12 ошибок и ненулевой код завершения при провале. Ошибка компиляции означает, что метод не запустился; прочитай её, исправь и повтори запуск.

Это реальная проверка поведения для заданных случаев, **не проверка понимания, быстродействия или работы в Godot**. Запускай только код, который готов выполнить локально: изоляции произвольного кода здесь нет. Для телефона GitHub Codespaces может быть удобным удалённым терминалом, если он доступен в твоём аккаунте; вход, ограничения и наличие SDK необходимо проверить самостоятельно. Прогресс этого локального задания пока не синхронизируется с веб-приложением автоматически.

## Защита решения

1. Почему простой вычет не подходит для `(5, 99)`?
2. Чем исключение отличается от возвращаемого значения? Почему здесь недопустимый вход обрабатывается отдельно?
3. Напиши другой тест, который не копирует ни один пример из задания; объясни ожидаемый результат.
4. Что изменится, если разрешить отрицательный урон? Сначала определи новую договорённость и тесты, а потом меняй код. Текущая проверка такой вариант не засчитает — она проверяет исходное ТЗ.

Если тесты прошли, вернись завтра и реши задачу заново без просмотра своего кода. Затем попробуй сделать консольную оболочку из урока 1, которая проверяет текстовый ввод и использует этот метод. Сохрани объяснения и изменения отдельными коммитами.
